# v1.8.1 Implementation: Separate qb_qp_mismatch Log File

**Date**: 2025-11-25
**Version**: v1.8.1 (enhancement to v1.8)
**Author**: Claude Code

## Overview

Separated `qb_qp_mismatch` log entries from `uncertain_or_expandable_issues.txt` into a dedicated log file for better issue tracking and data quality analysis.

## Motivation

The `qb_qp_mismatch` issue type (Strong's numbers in qb.php but not in qp.php) was the most common logged issue (117+ entries in Genesis alone), mixing FHL database completeness concerns with actual parsing ambiguities. This made it difficult to:

1. Focus on actionable parsing issues requiring spec expansion
2. Track FHL API data quality separately
3. Analyze patterns in morphology data gaps
4. Determine if issues are UNV-specific or affect other translations

## Log File Structure

### 1. strong_number_from_qb.php_not_found_in_qp.php.txt

**Purpose**: Strong's number mismatches between qb.php and qp.php

**Entry Format**:
```
[timestamp] verse_ref | qb_qp_mismatch | Strong's number <NNNNN> from qb.php not found in qp.php records. | KJV info
```

**Example**:
```
[2025-11-25 01:57:42] Gen 3:14 | qb_qp_mismatch | Strong's number <03212> from qb.php not found in qp.php records. | KJV also uses <03212>
```

**Use Cases**:
- Track FHL database completeness
- Identify patterns in missing morphology data
- Cross-reference with KJV to determine scope (UNV-specific vs broader)
- Focus on data quality rather than parsing logic

### 2. uncertain_or_expandable_issues.txt

**Purpose**: Parsing ambiguities requiring spec expansion (excluding qb_qp_mismatch)

**Issue Types**:
- `brace_attach_ambiguous` - Cannot determine preposition attachment
- `dangling_p900x` - Prefix without core token (12 Genesis entries)
- `dangling_object_marker` - אֵת without suitable noun (4 Genesis entries)
- `dangling_brace_prep` - Brace preposition without attachment point (2 Genesis entries)

**Benefit**: Cleaner focus on actionable parsing logic issues

### 3. compatible_but_notable_issues.txt

**Purpose**: Successfully parsed but notable cases (unchanged from v1.8)

### 4. compound_prep_plus_noun.txt

**Purpose**: Detected prep+noun compounds not merged per config (unchanged from v1.7)
