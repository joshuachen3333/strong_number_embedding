# v1.7.1 Bug Fix: Duplicate Logging of Prep+Noun Compounds

**Date**: 2025-11-24
**Status**: ✅ Fixed and Tested
**Affected Component**: `parse_verse_v1_7.py` logging logic

---

## Problem Description

### Issue
When parsing verses with `<04480>` (מִן) prep+noun compounds, the parser was logging the same issue to BOTH log files:
1. ❌ `uncertain_or_expandable_issues.txt` - as `qb_qp_mismatch`
2. ✅ `compound_prep_plus_noun.txt` - as `prep_noun_compound`

### Example (Gen 2:23)
The verse contains three instances of `<04480>` forming prep+noun compounds:
- `<04480><06106>` = מֵעֶצֶם "from bone"
- `<04480><01320>` = מִבָּשָׂר "from flesh"
- `<04480><00376>` = מֵאִישׁ "from man"

**Before fix**:

This is **redundant** and **misleading** because:
- The `qb_qp_mismatch` is explained by the compound detection
- Users see false "uncertainty" in verses that are actually properly handled
- Impact: ~1,097 verses affected across Genesis, Exodus, Leviticus

## Root Cause Analysis

### Detection Logic (Pass 0) - ✅ Working
```python
# parse_verse_v1_7.py lines 173-192
if PROFILE['detect_compounds_from_qp']:
    for i, token in enumerate(tokens):
        if token['value'] == '04480':
            compound_info = detect_min_compound(token, tokens[i + 1], qp_records)
            if compound_info and not compound_info['should_merge']:
                tokens[i]['_unmerged_compound'] = compound_info  # ✅ Marker set here
```

### Group Creation (Pass 1) - ❌ Marker Not Preserved
```python
# lines 229-239 (BEFORE FIX)
if token['type'] in ['strong', 'implicit_strong']:
    items.append({
        "core": token['value'],
        "implicit": token['type'] == 'implicit_strong',
        "_is_group": True,
        "_token": token,  # ✅ Token with marker copied
        "prefixes": [], "morph": [], "pre_brace": [], "post_brace": [],
        "warnings": [], "source_type": token['type']
    })
```

### Cleanup (Pass 2 end) - ❌ Marker Lost
```python
# line 294
item.pop('_token', None)  # ❌ Removes entire _token dict, including _unmerged_compound
```

### Formatting Phase - ❌ Marker Not Found
```python
# lines 375-390 (BEFORE FIX)
if not qp_info:
    note = f"Strong's number <{group['core']}> from qb.php not found in qp.php records."
    uncertainty_notes.append(note)  # ❌ Always added

    # Check for compound (but _token is already removed!)
    is_prep_noun_compound = group.get('_token', {}).get('_unmerged_compound') is not None  # ❌ Always False

    if is_prep_noun_compound:  # ❌ Never reached
        append_to_log(PREP_NOUN_LOG, ...)
    else:
        append_to_log(UNCERTAIN_LOG, ...)  # ❌ Always logs here
```

**Result**: All `<04480>` tokens without qp_info logged to `uncertain_or_expandable_issues.txt` even when they're explained by compound detection.

---

## Solution

### Fix 1: Preserve Marker at Group Level (Pass 1)
```python
# lines 229-239 (AFTER FIX)
if token['type'] in ['strong', 'implicit_strong']:
    group = {
        "core": token['value'],
        "implicit": token['type'] == 'implicit_strong',
        "_is_group": True,
        "_token": token,
        "prefixes": [], "morph": [], "pre_brace": [], "post_brace": [],
        "warnings": [], "source_type": token['type']
    }
    # v1.7.1: Preserve _unmerged_compound at group level (survives cleanup)
    if '_unmerged_compound' in token:
        group['_unmerged_compound'] = token['_unmerged_compound']  # ✅ Copied to group
    items.append(group)
```

### Fix 2: Check Group Directly (Formatting Phase)
```python
# lines 379-393 (AFTER FIX)
if not qp_info:
    note = f"Strong's number <{group['core']}> from qb.php not found in qp.php records."

    # v1.7.1: Check group directly (not _token, which gets removed during cleanup)
    is_prep_noun_compound = '_unmerged_compound' in group  # ✅ Direct check

    if is_prep_noun_compound and verse_ref:
        # This is a detected prep+noun compound that wasn't merged
        compound_info = group['_unmerged_compound']
        detail_note = f"Prep+noun compound detected: <04480><{next_sn}> = {compound_info['hebrew']} ({compound_info['structure']}) - not merged per config"
        append_to_log(PREP_NOUN_LOG, verse_ref, "prep_noun_compound", detail_note)
        # ✅ Do NOT add to uncertainty_notes or UNCERTAIN_LOG
    elif verse_ref:
        # ✅ Only log to UNCERTAIN_LOG if NOT a compound
        uncertainty_notes.append(note)
        append_to_log(UNCERTAIN_LOG, verse_ref, "qb_qp_mismatch", note)
```

### Fix 3: Improve qp.php Lookup for Compounds
```python
# lines 64-77 (AFTER FIX)
def detect_min_compound(token_04480, next_token, qp_records):
    # ...

    # Get ALL qp.php records for the next token (there may be multiple entries)
    next_sn = next_token.get('value')
    next_sn_stripped = next_sn.lstrip('0')

    # Find the qp record that contains מִן in wform (not just first match)
    qp_record = None
    for record in qp_records:
        if 'sn' in record and record['sn'].lstrip('0') == next_sn_stripped:
            if 'מִן' in record.get('wform', ''):
                qp_record = record  # ✅ Find compound record specifically
                break
```

**Why needed**: Some Strong's numbers have multiple qp.php entries (e.g., `06106` has both standalone and compound forms). The original logic returned the first match, potentially missing the compound entry.
