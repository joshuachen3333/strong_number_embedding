## 四件套

| 檔案 | 路徑範例 | 角色 |
|---|---|---|
| **source corpus** | `data/sources/WLC.tsv` | 原文 token 表(含 Strong / lemma / morph) |

## BCVWP token ID 解剖

**Source(12 碼 + canon 前綴)**

```
o 01 001 001 001 2
│  │   │   │   │  └─ Part    詞素序(1=前綴, 2=詞幹…)
│  │   │   │   └──── Word    詞序
│  │   │   └──────── Verse   節
│  │   └──────────── Chapter 章
│  └──────────────── Book    卷(01=創世記)
└─────────────────── Canon   o=舊約, n=新約(macula prefix)
```

**Target(11 碼,無前綴、無 part)**

```
01 001 001 003
Book Chap Verse Word
```

> ⚠️ **兩側不對稱**:原文有詞素切分(part),譯文沒有。這正是希伯來文前綴能單獨對齊的基礎。

# WLC.tsv 深入:為什麼 source 裡有英文和中文?

> 常見疑問:source 不是應該只有希伯來文(OT)或希臘文(NT)嗎?

## 因為它不是「文本」,是「帶多層註解的 token 表」

**`WLC.tsv` 不是一份希伯來文文本,而是一張 token 表。**

九個欄位裡,**只有 `text` 一欄是原文**;其餘八欄都是**關於這個 token 的後設資料**。英文和中文出現在 `gloss` / `gloss2`,那是**註解層**,不是經文內容。

```
o010010010012 | רֵאשִׁ֖ית-1 | רֵאשִׁ֖ית | H7225 | beginning | 起初 | רֵאשִׁית | noun | ncfsa
      ↑            ↑             ↑         ↑        ↑         ↑        ↑        ↑      ↑
     身分        可讀標籤      【原文】   字典鍵   英文註解  中文註解  字典形  詞類  構形
                            ← 唯一的希伯來文 →   ←──────── 全部是註解 ────────→
```

> **類比**:這像圖書館的**書目卡**,不是書本身。卡片上有書名(原文)、分類號、摘要、標籤——**摘要用什麼語言寫,不影響那本書是希伯來文寫的**。

## 設計目的

**讓下游工具不必自己解析希伯來文。** 對齊、詞彙查詢、對照顯示、形態搜尋,全部可以逐 token 進行。Macula 把「讀懂希伯來文」這件事**預先做完並固化成欄位**。

## 九個欄位逐一解釋(創 1:1 實例)

| 欄位 | 值 | 作用 |
|---|---|---|
| `id` | `o010010010012` | **BCVWP 身分**:o=舊約, 01=創, 001 章, 001 節, 001 詞, part **2** |
| `altId` | `רֵאשִׁ֖ית-1` | 人類可讀標籤,含出現序 |
| **`text`** | **`רֵאשִׁ֖ית`** | **← 原文本體**(帶母音 + 重音符) |
| `strongs` | `H7225` | 字典鍵(**我們的 join key**) |
| `gloss` | `beginning` | 英文註解(**隨文脈**) |
| `gloss2` | `起初` | 中文註解 |
| `lemma` | `רֵאשִׁית` | 字典形(去變化) |
| `pos` | `noun` | 詞類 |
| `morph` | `ncfsa` | 構形碼 |

## 五個關鍵設計,各舉實例

### ① 一個「詞」拆成多個 part —— 詞素才是單位

創 1:1 的 `בְּרֵאשִׁית` 視覺上是一個字,但是**兩個詞素**:

```
o010010010011  בְּ         H0871a  prep  Pp      ← part 1:介系詞前綴
o010010010012  רֵאשִׁ֖ית   H7225   noun  ncfsa   ← part 2:名詞詞幹
```

**這正是希伯來文前綴能單獨對齊的基礎。** 中文 / 英文沒有這層。

### ② 詞素可疊到三、四段

**三段**(創 1:5 `לָאוֹר֙` =「to the light」):

```
word o01001005003
  part1  לָ        H3807a  prep  Pp     to      ← 介系詞
  part2  (無形)     H1886a  art   Pa     the     ← 冠詞(母音化,無獨立字母)
  part3  אוֹר֙     H0216   noun  ncmsa  light   ← 名詞詞幹
```

**四段**(創 1:5 `וְלַחֹ֖שֶׁךְ` =「and to the darkness」,全庫最複雜的型態):

```
word o01001005005
  part1  וְ        H2050b  cj    Pc     and
  part2  לַ        H3807a  prep  Pp     to
  part3  (無形)     H1886a  art   Pa     the
  part4  חֹ֖שֶׁךְ   H2822   noun  ncmsa  darkness
```

**一個希伯來字 = 四個 token。** 英文要四個詞、中文要好幾個字才能表達的,希伯來文黏成一個字。

> 注意 `part2` / `part3` 的**冠詞 `text` 是空的** —— 定冠詞 הַ 在此已融入母音符號,沒有獨立字母,但 Macula **仍為它建立一個 token**。這是「詞素才是單位」最極端的體現。

**創世記詞素數分布**:

| 詞素數 | word 數 |
|---:|---:|
| 1 | 10,110 |
| 2 | 9,186 |
| 3 | 1,190 |
| 4 | 60 |

### ③ `altId` 解決同形詞歧義

創 1:1 有**兩個** `אֵת`:

```
o010010010041  altId=אֵ֥ת-1   ← 本節第 1 個
o010010010062  altId=אֵ֥ת-2   ← 本節第 2 個
```

純看 `text` 無法分辨,`altId` 加上出現序才能唯一指認。

### ④ `gloss` 隨文脈,`lemma` 不隨 —— 兩者分工

同一個 `וְ`(H2050b)在創 1:2 出現四次,`gloss` 各不相同:

| id | gloss | gloss2 |
|---|---|---|
| `...020011` | now | 且 |
| `...020041` | and | 又 |
| `...020051` | *(空)* | 且 |
| `...020091` | and | 且 |

但 `lemma` 全部都是 `וְ`。

> **`gloss` 是「這裡怎麼理解」,`lemma` 是「它是哪個詞」。**
> 我們 join 用 `strongs` / `lemma`,**不用 `gloss`**,原因就在這。

### ⑤ `morph` 構形碼 —— 高度壓縮的語法資訊

```
vqp3ms  = verb · qal · perfect · 3rd · masculine · singular   (בָּרָא 他創造了)
ncfsa   = noun · common · feminine · singular · absolute      (רֵאשִׁית)
ncmsc   = noun · common · masculine · singular · construct    (附屬形)
psn3ms  = pronoun · suffix · 3rd · masculine · singular       (後綴「他的」)
Pp / Pc / Pa / Po = 介系詞 / 連接詞 / 冠詞 / 受詞記號
```

全庫最高頻:`Pp`(64,313)、`Pc`(58,226)、`np`(34,774 專名)、`Pa`(31,150)。

> **注意 `c`(construct 附屬形)vs `a`(absolute 絕對形)** —— 這是希伯來文「A 的 B」結構的標記,`ncmsc` 表示「這個名詞後面還連著下一個」。

## 順帶:神名的證據在這裡也看得到

```
יְהוָ֥ה | H3068 | gloss=Yahweh | gloss2=雅威 | morph=np
```

`gloss`=Yahweh、`gloss2`=雅威 —— 這是 **Macula 的註解慣例(音譯)**,不是譯本選擇。
和合本作「**耶和華**」、呂振中作「**永恆主**」,**都跟這裡不同**。

再次印證:**`gloss2` 是註解層,不是翻譯層。**

## 回到 s13

我們要產的 UNV **target 檔只有 7 欄,沒有任何 gloss**:

```
id, source_verse, text, skip_space_after, exclude, id_range_end, source_verse_range_end
```

**source 端的豐富註解(Strong / lemma / morph / gloss)是 Macula 給的,我們只消費不生產。**

s13 的工作是把 UNV 的中文 token 接到這些既有的 source token 上 —— **用 `strongs` 當主鍵,用 `lemma` 驗證,`gloss2` 只作弱參考。**

# 實例一:創世記 1:1(希伯來 → 英文)

## ① source corpus 真實列(`WLC.tsv`)

```
id              text        strongs  gloss      gloss2  lemma      pos   morph
o010010010011   בְּ          H0871a   in                 בְּ         prep  Pp
o010010010012   רֵאשִׁ֖ית     H7225    beginning  起初    רֵאשִׁית    noun  ncfsa
o010010010021   בָּרָ֣א       H1254    he created 创造    ברא_1      verb  vqp3ms
o010010010031   אֱלֹהִ֑ים     H0430    God        神      אֱלֹהִים    noun  ncmpa
o010010010041   אֵ֥ת         H0853    -          -       אֵת_1      om    Po
o010010010051   הַ          H1886a   the                הַ         art   Pa
o010010010052   שָּׁמַ֖יִם     H8064    heavens    诸天    שָׁמַיִם    noun  ncmpa
o010010010061   וְ          H2050b   and        与      וְ         cj    Pc
o010010010062   אֵ֥ת         H0853    -          -       אֵת_1      om    Po
o010010010071   הָ          H1886a   the                הַ         art   Pa
o010010010072   אָֽרֶץ        H0776    earth      地      אֶרֶץ       noun  ncfsa
```

**關鍵觀察**:`בְּרֵאשִׁית`(在起初)被切成**同一個 word 的兩個 part**:

- `...0011` = `בְּ`(介系詞前綴)
- `...0012` = `רֵאשִׁית`(名詞詞幹)

### 順帶:`gloss2` 欄帶簡體中文

`gloss2` 有中文 glosses(起初 / 创造 / 神 / 诸天 / 与 / 地)。**完整度已實測量化,見下節。**

用途界線要先劃清:

- ✅ **可作事後交叉驗證** —— join 出「起初 ↔ רֵאשִׁית」時,`gloss2` 也寫「起初」,是獨立的第二證據(同 lemma 驗證變體表之理)
- ❌ **不可作輸入** —— s11 文件明訂 *"the Chinese `gloss2` column is always dropped"*,餵進去會造成**中文答案洩漏**

## ② target corpus 真實列(`ot_BSB.tsv`)

```
01001001001  In          01001001007  heavens
01001001002  the         01001001008  and
01001001003  beginning   01001001009  the
01001001004  God         01001001010  earth      ← skip_space_after=y
01001001005  created     01001001011  .          ← exclude=y
01001001006  the
```

## ③ alignment file 真實 record

```json
{
  "source": ["o010010010011", "o010010010012"],
  "target": ["01001001001", "01001001002", "01001001003"],
  "meta":   {"id": "01001001.001", "origin": "manual", "status": "created"}
}
```

全節攤開:

| record | 原文 | ↔ | 英文 | 比例 |
|---|---|---|---|---|
| `.001` | בְּ + רֵאשִׁית | → | In the beginning | **2:3** |
| `.002` | בָּרָא | → | created | 1:1 |
| `.003` | אֱלֹהִים | → | God | 1:1 |
| **`.004`** | **(不存在)** | | | ⚠️ |
| `.005` | הַ + שָּׁמַיִם | → | the heavens | 2:2 |
| `.006` | וְ + אֵת | → | and | **2:1** |
| `.007` | הָ + אָרֶץ | → | the earth | 2:2 |

## 這一節示範的五個現象

1. **詞素獨立對齊** —— `בְּ`(part 1)與 `רֵאשִׁית`(part 2)一起對到 "In the beginning"
2. **語序重排** —— `בָּרָא`(原文第 **2** 字)對到英文第 **5** 字;`אֱלֹהִים`(第 3 字)對到英文第 **4** 字
3. **未對齊 token** —— **`.004` 整筆記錄不存在**,因為 `o010010010041` = `אֵת`(H0853 受詞記號,gloss 為 `-`)在英文無對應詞。**Burrito 的作法是乾脆不建記錄,而非建一筆空的**
4. **標點不參與對齊** —— `01001001011`(`.`,`exclude=y`)不出現在任何 record
5. **非 1:1 是常態** —— 2:3、2:1、2:2 皆有

# `gloss2` 中文覆蓋度 — 實測量化

> 量測日:2026-07-31。判定「含中文」= `gloss2` 非空、非 `-`,且含 CJK 字元(`[一-鿿]`)。

## 總覽:舊約近乎滿覆蓋,新約完全沒有

| 檔案 | 總 token | `gloss2` 非空 | **含中文** | |
|---|---:|---:|---:|---|
| **`WLC.tsv`**(OT) | 475,012 | 417,964 (88.0%) | **417,932 (88.0%)** | ✅ 全 39 卷 |
| **`SBLGNT.tsv`**(NT) | 137,741 | 133,103 (96.6%) | **0 (0.0%)** | ❌ **無中文** |

## `gloss2` 到底有幾種語文?—— **只有 2 種,不是 10 種**

常見誤解:`data/` 底下有 10 個語言資料夾,所以 `gloss2` 應該也有 10 種語文。**不是。**

掃描**全部 6 個來源檔** × **10 種書寫系統**(漢字 / 拉丁 / 希伯來 / 希臘 / 阿拉伯 / 西里爾 / 天城 / 孟加拉 / 韓文 / 假名),**只命中 2 種**:

| 來源檔 | 總 token | `gloss2` 非空 | 書寫系統 |
|---|---:|---:|---|
| **`WLC.tsv`** | 475,012 | **88.0%** | **CJK 漢字 100%**(簡體中文) |
| `SBLGNT.tsv` | 137,741 | 96.6% | Latin 100%(英文) |
| `SBLGNT+required.tsv` | 137,741 | 96.6% | Latin 100%(英文) |
| `WLCM.tsv` | 469,476 | 33.6% | Latin 100%(英文) |
| `WLCM+required.tsv` | 469,476 | 33.6% | Latin 100%(英文) |
| `BGNT.tsv` | 138,131 | **0.0%** | (完全空) |

**結構原因**:`gloss2` 是**來源檔的單一欄位**,每個檔只有一欄,**結構上就只能裝一種語文**。

而且**中文只存在於 `WLC.tsv` 這一個檔** —— 連它的孿生檔 `WLCM.tsv` 都是英文(且只填了 33.6%)。這是 Macula 內部的不對稱:**希伯來側的第二 gloss 給了中文,希臘側給的是簡化英文。**

### 那 10 個語言在哪裡?

在 **target 端**,而且**不是 gloss,是譯文本身**:

```
arb: كِتَابُ مِيلَادِ يَسُوعَ ٱلْمَسِيحِ
hin: आदि में परमेश्वर ने आकाश
rus: В начале сотворил Бог небо и землю
```

抽查 `eng` / `arb` / `hin` / `rus` 四語言的 target 檔,欄位**完全相同且都沒有 gloss 欄**:

```
id, source_verse, text, skip_space_after, exclude, id_range_end, source_verse_range_end
```

| 層 | 內容 | 語言數 |
|---|---|---|
| **source** 端 | 原文 token + `gloss` / `gloss2` **註解** | 註解 2 種(中 / 英) |
| **target** 端 | 各語言的**實際譯文** | **10 語言 / 12 譯本** |

> **對 s13 的直接影響**:我們要產的 UNV 屬 **target 端**,**不需要也不應該產 gloss 欄**。目標檔案結構就是那 7 欄。

> ## ⚠️ 關鍵不對稱
> **中文 gloss 只存在於希伯來文舊約。** 希臘文的 `gloss2` 是**第二個(簡化的)英文 gloss**,不是中文:
>
> ```
> Βίβλος     gloss="[The] book"          gloss2="book"
> γενέσεως   gloss="of [the] genealogy"  gloss2="genealogy"
> ```
>
> 所以「Alignments 有中文 gloss」這句話**只對舊約成立**。s13 推進到新約時,這層驗證訊號會消失。

# `gloss2` 是哪個中文譯本?—— **都不是**

實測回答三個問題:它是 UNV 的斷詞嗎?是 LCC 的斷詞嗎?是哪個出版譯本?

## ① 字面吻合率:對 UNV 與 LCC **等距**

創世記 1–5,檢查 `gloss2` 的詞是否出現在譯文字面中(已用 `opencc` 轉正體):

| 譯本 | gloss2 詞出現於字面 |
|---|---:|
| **UNV** 和合本 | 1,224 / 2,411 = **50.8%** |
| **LCC** 呂振中 | 1,196 / 2,411 = **49.6%** |

**差距僅 1.2 個百分點。** 若 `gloss2` 源自其中之一,該譯本應明顯較高——它對兩者「等距」,正說明**獨立於兩者**。

以 Strong 為主鍵逐詞比對 UNV(創 1–5,1,776 個可比對 token):

| | 數量 | 比例 |
|---|---:|---:|
| 完全相同 | 501 | **28.2%** |
| 互相包含 | 347 | 19.5% |
| **完全不同** | 928 | **52.3%** |

只有 28% 逐字相同。**若它是 UNV 的斷詞,這個數字應該接近 100%。**

## ② 神名三方全異 —— 決定性證據

| | אֱלֹהִים (H430) | יהוה (H3068) |
|---|---|---|
| **`gloss2`** | **神** | **雅威** |
| **UNV** 和合本 | 神 | **耶和華** |
| **LCC** 呂振中 | **上帝** | **永恆主** |

實際經文:

```
gloss2 :  起初 | 創造 | 神 | 諸天 | 地
UNV    :  起初，　神創造天地。
LCC    :  起初上帝創造天地。

UNV    :  ...在耶和華　神造天地的日子...
LCC    :  ...當永恆主上帝造地造天的日子...
```

**「雅威」不為和合本或呂振中所採用**,而 `gloss2` 用的是「**神 + 雅威**」這組**不吻合任何單一出版譯本**的組合。

LCC 缺失詞的前幾名,全是系統性用字差異:

| `gloss2` 詞 | LCC 沒有的原因 |
|---|---|
| **神**(65 次) | LCC 一律用**上帝** |
| **雅威**(31 次) | LCC 用**永恆主** |
| 諸天(15 次) | LCC 用**天** |
| 且 / 又 / 於是 / 而 / 及(200+ 次) | 連接詞 וְ 譯法各異 |

## ③ 它含 gloss 專用標記,且隨形態不隨文脈

**`~` 標記**(34,535 個 token,佔 8.3%):

```
~面前 (H6440)     ~的神 (H430)     他~说 (H559)
```

`~` 是**註解慣例符號**(標示附屬形等語法關係)。**任何真實譯本都不會出現這種符號** —— 這是決定性的。

**同一 Strong 的 `gloss2` 變體全屬語法,而非文學選擇**:

| Strong | 最常見三種 `gloss2` | 變化軸 |
|---|---|---|
| H1961 (היה) | 有 / **他是** / 是 | 隨**人稱** |
| H559 (אמר) | 说 / **他说** / **他~说** | 隨**人稱 + 附屬** |
| H3117 (יום) | 日 / 日子 / **之日** | 隨**格位** |
| H430 (אלהים) | 神 / **~的神** / 的神 | 隨**附屬形** |

全庫 8,420 個 Strong 中,**44.6% 只有一種寫法**;多寫法者差異都在「他-」「之-」「~的-」這類語法標記上。

## 與 UNV 的實際差異樣態

| Strong | `gloss2` | UNV | 差異性質 |
|---|---|---|---|
| H8064 | 諸天 | **天** | gloss 較直譯 |
| H8415 | 深淵 | **淵** | 同上 |
| H3117 | 日 | **晝** | 用詞不同 |
| H7363 | 覆煦 | **運行** | 用詞不同 |
| H1961 | 是 | **要有 / 就有了 / 有** | UNV 隨文脈,gloss 不隨 |
| H8414 / H922 | 混沌 / 空虛 | **空虛 / 混沌** | ⚠️ **對應相反** |

最後一列:`תֹהוּ וָבֹהוּ`,Macula 註 H8414=混沌、H922=空虛;UNV 譯「空虛混沌」,按位置對應**剛好反過來**。這是**真實的語義歸屬分歧**,不是簡繁或用字問題。

## 結論

| 問題 | 答案 |
|---|---|
| 是 UNV 的斷詞嗎? | **不是**(逐字 28.2%,字面 50.8%) |
| 是 LCC 的斷詞嗎? | **不是**(字面 49.6%,神名全異) |
| 是哪個中文譯本? | **都不是**。它是 Macula 自製的**逐詞形態註解**,神名採「神 / 雅威」這組不屬於任何主流譯本的慣例 |

## 對 s13 的實際意義

**✅ 好消息**

舊約的交叉驗證訊號**近乎滿覆蓋**,而且**缺口與我方的缺口重疊**:`gloss2` 缺的是冠詞/受詞記號,正好也是 Strong-join 本來就對不齊的虛詞。兩者不衝突。

**⚠️ 三個限制**

1. **新約完全沒有這個訊號** —— s13 推進到 SBLGNT 側時,驗證手段只剩 `lemma`,少一層保險。
2. **簡繁不同** —— `gloss2` 是**簡體**(创造 / 诸天 / 与),UNV 是**正體**(創造 / 諸天 / 與)。要當驗證訊號**必須先做簡繁轉換**,不能直接字串比對。
3. **它是 gloss,不是譯文** —— `gloss2` 給的是逐詞對照(「诸天」),UNV 實際用字是「天」。

4. **它不是任何譯本的斷詞** —— 見上節。切分邏輯是**希伯來詞素**,不是中文詞。UNV 的斷詞仍須從 **FHL 的 SN 標籤邊界**反推。

> ### 最重要的界線(經三輪實測修正)
>
> **`gloss2` 只能用來「否證明顯錯誤」,不能用來「確認正確」。**
>
> - ✅ 若 join 出的中文詞與 `gloss2` **毫無字面關聯**(如「光 ↔ 因」),多半是對錯了 → **可作否證**
> - ❌ 但**字面不同不代表對錯** —— 晝/日、運行/覆煦、天/諸天 **都是對的** → **不可作確認**
>
> **真正的判準始終是 Strong 號**;`lemma` 是第一驗證層,`gloss2` 只是弱參考。

## 重現指令

```bash
cd ../Alignments
python3 - <<'EOF'
import re, collections
CJK = re.compile(r'[一-鿿]')
def survey(path, label):
    tot = cjk = 0
    with open(path, encoding='utf-8') as f:
        f.readline()
        for line in f:
            fl = line.rstrip('\n').split('\t')
            if len(fl) < 6: continue
            tot += 1
            g2 = fl[5].strip()
            if g2 and g2 != '-' and CJK.search(g2): cjk += 1
    print(f"{label}: {cjk:,}/{tot:,} = {100*cjk/tot:.1f}% 含中文")
survey('data/sources/WLC.tsv',    'WLC (OT)')
survey('data/sources/SBLGNT.tsv', 'SBLGNT (NT)')
EOF
```

## 中文的比例正好反轉

英文是 **2:3**(`בְּרֵאשִׁית` → "In the beginning"),中文是 **2:1**(→「起初」)。

中文更緊湊,**多對一是常態** —— 這對對齊演算法反而是**好事**(候選空間更小)。

## 但中文有個獨有難點

**英文靠空格就能切 token,中文不行。**

上表的 target corpus 看似簡單,實際上「起初 / 神 / 創造 / 天 / 地」這個切法是從 **FHL 的 SN 標籤邊界**反推出來的 —— SN 貼在哪個字後面,就切在哪裡。

**這正是 [s12](../survey12_segment_target_verse/) 存在的理由**:一旦 UNV 的 token 邊界被原文錨定,`LCC`、`RCUV2010` 這些**沒有 SN** 的譯本就有了原文級的分詞參照框架,不必盲目斷詞。
