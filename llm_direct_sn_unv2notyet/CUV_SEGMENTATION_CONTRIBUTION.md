## 1. 先修正前提

問題是「這個 repo 應該已經有 `UNV.tsv`」。**沒有。**

`text-align` 帶的中文目標資料叫 **CUV**（Biblica 對和合本的代號），三個檔：

```
data/alignments/alignments-cmn/data/targets/CUV/
    token_CUV.tsv   704,373 列   24 MB   kathairo 原始輸出（全本未切）
    ot_CUV.tsv      530,705 列   18 MB
    nt_CUV.tsv      173,670 列  5.8 MB
```

欄位是 `id / source_verse / text / skip_space_after / exclude / id_range_end /
source_verse_range_end / required`。

**沒有 SN 欄位。** 這是 kathairo 從 USFM 產出的純逐詞 TSV。

所以「這個計畫已經幫我們幾乎都做出來了」要拆成兩半回答：

| 我們缺的 | CUV TSV 給不給得起 |
|---|---|
| **詞邊界**（中文斷詞） | **給得起** —— 全本、現成、與 FHL 邊界 89% 相容、粒度比 FHL 更細 |
| **Strong's Number** | **給不起** —— TSV 無此欄；要靠對齊反推，而對齊只有 3 章 |

而且我們**本來就不缺 SN**：FHL 的 UNV+SN 已經涵蓋全本 31,103 節。
缺的從頭到尾就是詞邊界。CUV TSV 補的正是這一塊。

## 2. 兩份文本可以對齊嗎？可以，四項機械差異

FHL `bible_unv.json` 與 CUV TSV 全本逐節比。四項差異都可機械處理：

| # | 差異 | FHL | CUV | 處理 |
|---|---|---|---|---|
| 1 | 神名 | 神版（神 4,765） | 上帝版（上帝 4,085） | `上帝` → `神` |
| 2 | 異體字 | `著` 2,648 / `裡` 4,770 | `着` 2,636 / `裏` 4,755 | 統一為 `着`/`裏` |
| 3 | 標點空白 | 全形標點、`　` | 獨立的 `exclude=y` 詞元 | 一律去除 |
| 4 | 內嵌譯註 | 1,393 處 | 246 節 | 各自剝除 |

正規化後：

| 類別 | 節數 |
|---|---:|
| 完全相同 | 24,426 |
| 僅異體字差 | 6,031 |
| 實質差異 | **564** |

### 2.1 第 1 項必須對整串做

`上帝` → `神` 不能逐詞元替換，因為 kathairo 會把「上帝」切斷：

```
創 5:1   01005001009  當上      ← 切在這裡
         01005001010  帝
```

全本「上帝」作為單一詞元 3,860 次，但被切斷的情形確實存在。
`normalize_tokens()` 對整串做替換，並把落在合併字串內部的邊界丟棄
（那本來就是切分錯誤）。這一項讓可比節多了約 130 節。

### 2.2 第 4 項是雙向的

一開始以為只有 FHL 把譯註寫進經文，錯了 —— **CUV 有 246 節也含 `（…）`**，
而且「這句算正文還是註」兩邊判斷不一致，方向還是雙向的：

```
創 14:8   CUV  …和比拉王（比拉就是瑣珥）都出來…      ← CUV 當正文
          FHL  …和比拉王都出來…                      ← FHL 當譯註

創 8:21   CUV  …咒詛地，人從小時心裏懷着惡念，也不再…  ← CUV 當正文
          FHL  …咒詛地，也不再…                      ← FHL 當譯註
```

CUV 的括號本身是 `exclude=y` 的標點，**但括號內的文字是正常詞元**，
所以必須靠括號配對偵測，不能靠 `exclude` 欄。這一項讓可比節多了約 230 節。

### 2.3 剩下的 564 節是真版本差異

兩份都是和合本，但不是同一個版本。差異型態很一致：

```
創 14:15   北邊  /  左邊
創 24:48   合適  /  合式
創 27:2    那一天 / 哪一天
創 29:32   流便  /  呂便          ← 人名音譯
創 32:30   毘努伊勒 / 毗努伊勒      ← 地名音譯
```

**這類不該強行對齊。** 神版與上帝版的差異不只在神名，人地名音譯與用字都有系統性
出入。詳見 §8.2。

**節數落差**：CUV 多 116 節（詩篇標題編為第 0 節，如 `19003000`「大衛逃避他兒子
押沙龍的時候作的詩」）；FHL 多 82 節（民 1:21 等 CUV 併節處理）。

## 4. 邊界一致度：與 FHL SN 隱含切分比

FHL 的 SN 標籤本身就隱含切分：每個標籤標記其前方文字段的結尾。以此為基準，
在 **30,456 個可比節**上：

| | 數量 |
|---|---:|
| FHL 邊界 | 346,462 |
| kathairo 邊界 | 528,230 |
| 交集 | 308,526 |

| 指標 | 值 | 意思 |
|---|---:|---|
| **recall** | **89.1%** | FHL 的 SN 邊界，近九成也是 kathairo 詞元邊界 |
| precision | 58.4% | kathairo 切得比 FHL **細得多** |

**「更細」對我們是好事。** FHL 常把一個 SN 掛在多詞片語上 ——
`的兒子`、`的神`、`的子孫`、`就有了`、`是好的` ——
kathairo 會拆成 `的|兒子`、`就|有|了`。這正是我們要的粒度。

並排看：

```
創 1:1
  FHL : 起初 | 神 | 創造 | 天 | 地
  CUV : 起初 | 神 | 創造 | 天地              ← 唯一分歧：天地 該拆

約 3:16
  FHL : 神|愛|世人|甚至|將他的獨生|子|賜給|他們，叫|一切|信|他的|不|致滅亡|反|得|永|生
  CUV : 神|愛|世人|甚至|將|他的|獨生子|賜給|他們|叫|一切|信|他的|不致|滅亡|反|得|永生

太 1:1
  FHL : 亞伯拉罕|的後裔|大衛|的子孫|（…譯註…）耶穌|基督|的家|譜
  CUV : 亞伯拉罕|的|後裔|大衛|的|子孫|耶穌|基督|的|家譜
```

太 1:1 特別清楚：FHL 把 `的` 黏在右邊（`的後裔`）又把 `家譜` 拆成 `的家|譜`；
CUV 給出 `的|後裔` 與完整的 `家譜`。**CUV 的斷詞品質在這裡明顯較好。**

## 5. 要修的 6.35%：35,478 個過度合併詞元

558,686 個詞元中，**35,478 個（6.35%）內部含有 FHL 邊界** —— kathairo 把該分的黏住了。

### 5.1 集中度：可以用規則表處理

| 涵蓋範圍 | 佔全部過度合併 |
|---|---:|
| 前 50 型 | 20.2% |
| 前 200 型 | 37.2% |
| 前 500 型 | 51.4% |
| 前 1,000 型 | 64.0% |
| 前 2,000 型 | 76.9% |
| 全部 7,793 型 | 100% |

- **切點唯一的型：7,221 / 7,793（93%）** —— 一個詞型該切就切在同一個位置，不會搖擺。
- **每次出現都該切的型：3,613 / 7,793（46%）** —— 另一半是「有時該切、有時不該」。

### 5.2 那 46% 不是 FHL 標得不一致，是原文驅動的

高頻例 `以色列人`：1,009 次出現中 636 次該切。查 FHL 原文：

```
以色列<WH03478>人<WH01121>      ← 希伯來文有 בְּנֵי（「…的子孫」），人 有自己的 SN
以色列人<WH03478>               ← 希伯來文只有 יִשְׂרָאֵל，人 是譯者補的，無 SN
```

**這是原文差異，不是標註瑕疵。** 同理 `賜給`：`賜<WH05414><WTH8804>給你們` 對
`賜給<WH05414>`。

推論很直接：**較細的切分（永遠切）才是正確的基礎斷詞**，SN 投影那一層再處理
「這次 `人` 有 SN、那次沒有」的差異。切分與標註是兩件事，不該混在一起決定。

### 5.3 35,478 的兩類

| 類別 | 數量 | 佔比 | 性質 |
|---|---:|---:|---|
| **乾淨切分** | 24,098 | 67.9% | 詞元結尾也是 FHL 邊界，兩側各自成 chunk |
| **歸屬不一致** | 11,380 | 32.1% | 詞元右半在 FHL 眼中屬於下一個 chunk |

第一類直接切開就對了。高頻例：
`以色列人` `人子` `不再` `猶大王` `不能` `回答說` `眾民` `會幕` `全地` `今日` `來到`

第二類再細分：

| 子類 | 數量 | 佔比 | 例 |
|---|---:|---:|---|
| 其他（功能詞 + 代詞/名詞） | 6,352 | 55.8% | `因他` `不知` `在我` `名叫` `在那` `心裏` |
| 結構助詞 `的`/`地`/`得` | 3,106 | 27.3% | `他的` `人的` `你們的` `說的` `我們的` `所說的` |
| 動補/介詞 | 1,922 | 16.9% | `賜給` `臨到` `地上` `交在` `獻給` `交給` |

看實際 FHL 文本，這三類其實是**同一個現象**：中間那個字，FHL 往右黏、kathairo 往左黏。

```
因<WAH05921><WH0182>他兒子<WH01121>    FHL: 因 | 他兒子       CUV: 因他 | 兒子
不<WAH03808>知道<WH03045>              FHL: 不 | 知道         CUV: 不知 | 道
名<WH08034>叫基訓<WH01521>             FHL: 名 | 叫基訓       CUV: 名叫 | 基訓
他<WH0430>的形像<WAH09002>             FHL: 他 | 的形像       CUV: 他的 | 形像
賜<WH05414><WTH8804>給你們             FHL: 賜 | 給你們       CUV: 賜給 | 你們
```

兩邊各有對錯：`不|知道` FHL 正確（`不知|道` 是 kathairo 切錯）；
`他的|形像` 則是 CUV 較合中文語感，FHL 的 `的形像` 是被希伯來文的 construct
關係牽著走。

**所以對基礎斷詞而言，最穩的做法是取兩邊邊界的聯集** —— 得到
`他 | 的 | 形像`。這在 SN 工作上正是我們要的：`的` 常常自己承擔類似 900x 前綴的功能，
本來就該獨立成一個 token。

## 7. 投影已完成

`tools/cuv_segmentation/project.py` 把 FHL 的 SN 投影到 kathairo 的詞邊界上，
全本約 4 秒跑完。管線：

```
FHL UNV+SN
   ↓  剝除 （…）/【…】 譯註
   ↓     短註（1 個 SN 且含「原文」「或譯」）的 SN 掛回正文 —— 309 條
   ↓     其餘 1,084 條整段移出，存進 notes（含其 SN 與詞形碼）
   ↓  切成 SN 群組：每個標籤標記其前方文字段的結尾
   ↓  帶大括號的 {<…>} 往後掛（原文有、中文無對應字）
   ↓  與 kathairo 詞元邊界取聯集（CUV 側同樣先剝除自己的譯註、整串正規化）
產物  詞級 UNV+SN，31,061 節
```

### 7.1 三種邊界策略的實測

| 策略 | token 數 | 有 SN | 細化倍率 | **SN 守恆** | **詞形碼守恆** |
|---|---:|---:|---:|---:|---:|
| `fhl` 只用 FHL 邊界 | 384,788 | 96.4% | 1.00× | 0% 不符 | 0% 不符 |
| `kath` 只用 kathairo 邊界 | 566,307 | 97.0% | 1.58× | **50.4% 不符** | 13.1% 不符 |
| **`union` 聯集（預設）** | **604,252** | **96.9%** | **1.57×** | **0% 不符** | **0% 不符** |

`kath` 在半數節遺失 SN —— 因為 kathairo 較粗的地方（那 6.35% 過度合併）會把兩個
FHL 群組壓成一個 token，後者的 SN 無處可掛。`union` 同時做到**無損**與**比 FHL 細
1.57 倍**，是唯一兩者兼得的選項。

### 7.2 投影覆蓋率

| | 節數 |
|---|---:|
| 總節數 | 31,061 |
| 成功套用 kathairo 邊界 | **30,456（98.1%）** |
| 文本不符、退回純 FHL 切分 | 605（1.9%） |
| 含譯註（已移出正文） | 1,020 |
| 節尾孤兒 SN | 1,131 節 / 1,560 個 |

三項正規化修正把覆蓋率從最初的 30,103 推到 30,456：

| 修正 | 增加節數 |
|---|---:|
| 剝除 FHL 譯註（一開始就有） | 基準 |
| 整串正規化（修「上帝」被切斷） | 約 +130 |
| 剝除 CUV 自己的譯註 | 約 +230 |

剩下的 605 節仍有完整 SN，只是切分粒度退回 FHL 等級 —— **沒有任何一節被放棄**。

### 7.3 輸出格式

`output/_unv_sn_segmented/unv_sn.union.jsonl`（44 MB，一節一行）。
前綴底線讓 `generate_manifest.py` 略過它（沿用 `_archive_alias_era/` 慣例）。

```json
{"vid":"01001001","book":"創","chap":1,"sec":1,"seg":"union",
 "raw":"起初，　神創造天地。",
 "tokens":[{"i":0,"t":"起初","g":0,"sn":["H09002","H07225"],"m":[]},
           {"i":1,"t":"神",  "g":1,"sn":["H0430"],"m":[]},
           {"i":2,"t":"創造","g":2,"sn":["H01254"],"m":["8804"]},
           {"i":3,"t":"天",  "g":3,"sn":["H0853","H08064"],"m":[]},
           {"i":4,"t":"地",  "g":4,"sn":["H0853","H0776"],"m":[]}]}
```

`g` 是 SN 群組序號。**同一個 `g` 的多個 token 共用該群組的 SN**，例如
FHL 的 `分開了<WH0914>` 被 kathairo 切成 `分開|了`，兩者同屬 g7：

```
創 1:4   　神看光是好的，就把光暗分開了。
   g0 神    sn=[H0430]
   g1 看    sn=[H07200]  m=[8799]
   g2 光    sn=[H0853, H0216]
   g3 是    sn=[H03588, H02896]      ┐ 同群組，共用 SN
   g3 好的  sn=[H03588, H02896]      ┘
   g4 就    sn=[H0430]               ┐
   g4 把    sn=[H0430]               ┘
   g5 光    sn=[H0996, H0216]
   g6 暗    sn=[H0996, H02822]
   g7 分開  sn=[H0914]  m=[8686]     ┐
   g7 了    sn=[H0914]  m=[8686]     ┘
```

因為有 `g`，聯集的「切太細」是**可逆的** —— 依 `g` 合併就回到 FHL 粒度，
沒有資訊損失。這是選聯集的另一個理由。

三個附加欄位，都只在需要時出現：

| 欄位 | 意義 |
|---|---|
| `notes` | 移出的譯註，含 `t`（文字）、`sn`、`m`（詞形碼）。1,084 條 |
| `orphan_sn` | 節尾的括號標籤，後面沒有中文可掛（1,560 個） |
| `seg` | `union` 或 `fhl`，記錄該節實際用了哪種切分 |

### 7.4 譯註 SN 的掛回規則

1,393 條譯註中 844 條帶 SN。**掛回 309 條**，判準是「恰好 1 個核心 SN
**且**含『原文』或『或譯』」：

| 句式 | 條數 | 掛回？ | 理由 |
|---|---:|---|---|
| `原文是` / `原文作` / `原文` | 237 | ✅ | 「正文這個詞的原文是 X」，X 的 SN 屬於前一個正文詞 |
| `或譯` | 72 | ✅ | 同上，替代譯法 |
| `就是` | 2 | ❌ | `（比拉就是<WAH01931>瑣珥<WH06820>）` 是編者的地名對照，SN 是註本身的字 |
| 無關鍵詞 | 88 | ❌ | 混雜（`細拉` `或名示巴` `又作以色列人`），無法一概而論 |
| 2 個以上 SN | 444 | ❌ | 2-SN 已經混雜，5-SN 以上是整段替代譯法 |

實例：

```
創 14:14  FHL  他姪兒【原文是弟兄<WH0251>】被擄去
          →    他[H03588,H0251] | 姪兒[H03588,H0251] | 被擄[H07617] | …
```

未掛回的 1,084 條**連詞形碼一起**保存在 `notes`，沒有任何 SN 消失
（這正是 §7.5 SN 守恆能做到 0% 的原因）。

### 7.5 驗證

`tools/cuv_segmentation/validate.py` 三項檢查，`union` 與 `fhl` 全部通過：

| 檢查 | 結果 |
|---|---|
| 文本還原：token 串接 == FHL 原文（扣除譯註） | **0 不符** |
| SN 守恆：token ∪ orphan ∪ notes == 原文全部核心 SN（多重集） | **0 不符** |
| 詞形碼守恆：同上，針對 `<WT…>` | **0 不符** |

多重集比對意味著**連重複的 SN 都對得上**，不是只比集合。

## 9. 重現

```bash
cd llm_direct_sn_unv2notyet/tools/cuv_segmentation

python3 measure.py              # §2 §3 §4 §5 量化（約 3 分鐘）
python3 measure.py boundary     # 只跑 §4

python3 project.py              # 投影全本 → output/_unv_sn_segmented/（3.6 秒）
python3 project.py --book 01    # 只跑創世記
python3 project.py --boundary fhl

python3 validate.py             # 驗證預設輸出
python3 validate.py ../../output/_unv_sn_segmented/unv_sn.fhl.jsonl

python3 sn_check.py             # §6：對齊能還原多少 SN
```

`_common.py` 是共用載入層，定義了正規化與「FHL 隱含切分」的邊界規則 ——
後續工作應直接沿用，不要另寫一份正規化。

依賴：`original_text_preparation/bible_text_json/bible_unv.json` 與
`llm_direct_sn_unv2notyet/text-align/`（巢狀 clone，父 repo 未追蹤）。
